## 1. 摄像机本质

**摄像机 = 视图矩阵的交互式操控方式。**

在坐标系统章节中，我们直接用 `glm::lookAt` 生成视图矩阵：

```cpp
glm::mat4 view = glm::lookAt(
    glm::vec3(0.0f, 0.0f, 3.0f),    // 固定位置
    glm::vec3(0.0f, 0.0f, 0.0f),    // 固定目标
    glm::vec3(0.0f, 1.0f, 0.0f)     // 固定上方向
);
```

摄像机章节的核心变化是：**让位置和目标点变得动态可控**。

```cpp
glm::mat4 view = glm::lookAt(camPos, camPos + camFront, camUp);
//                                动态位置     动态目标      固定上方向
```

`camPos` 和 `camFront` 成为程序的核心状态变量，每帧通过用户输入更新。

### 摄像机三大要素

| 要素 | 变量 | 意义 |
|------|------|------|
| **位置 (Position)** | `camPos` | 摄像机在世界空间中的坐标 |
| **朝向 (Front)** | `camFront` | 摄像机看向的方向（单位向量） |
| **上向量 (Up)** | `camUp` | 定义摄像机顶部的方向（通常固定为 (0,1,0)） |

> **核心公式**：`view = lookAt(Position, Position + Front, Up)`

## 2. 欧拉角（Euler Angles）

### 2.1 为什么需要欧拉角？

直接操控 `camFront` 向量很困难（用户没法直观地输入一个三维单位向量）。欧拉角提供了直观的操控方式：

- **Yaw（偏航角）**：绕 Y 轴旋转，左右看
- **Pitch（俯仰角）**：绕 X 轴旋转，上下看

### 2.2 欧拉角转为方向向量

```cpp
glm::vec3 front;
front.x = cos(glm::radians(yaw)) * cos(glm::radians(pitch));
front.y = sin(glm::radians(pitch));
front.z = sin(glm::radians(yaw)) * cos(glm::radians(pitch));
camFront = glm::normalize(front);
```

**推导过程**（球面坐标转笛卡尔坐标）：

```
设 r = 1（单位向量），仰角从水平面算起：

x = r * cos(pitch) * sin(yaw)    - 使用 cos(yaw) * cos(pitch)
y = r * sin(pitch)                - 不变
z = r * cos(pitch) * cos(yaw)    - 使用 sin(yaw) * cos(pitch)

为什么 x 用 cos(yaw) 而 z 用 sin(yaw)？
因为我们想让 yaw = 0 时指着 -Z 方向，
所以使用「旋转过后再偏移 90 度」的三角组合，
配合默认 yaw = -90 度，最终 front = (0,0,-1)。
```

### 2.3 为什么初始化 yaw = -90 度？

```cpp
float yaw = -90.0f;  // 不能是 0
```

代入验证：

- 当 `yaw = -90, pitch = 0`：
  - `front.x = cos(-90) * cos(0) = 0 * 1 = 0`
  - `front.y = sin(0) = 0`
  - `front.z = sin(-90) * cos(0) = -1 * 1 = -1`
  - `front = (0, 0, -1)`：正确指向 -Z

- 如果 `yaw = 0`：
  - `front = (1, 0, 0)`：看向 X 正方向，错误

### 2.4 Pitch 的限制（防止万向锁）

```cpp
if (pitch > 89.0f)  pitch = 89.0f;
if (pitch < -89.0f) pitch = -89.0f;
```

为什么限制在 89 度而不是 90 度？

- Pitch = 90 度时 `cos(pitch) = 0`，导致 `front.x = front.z = 0`
- 此时 `front = (0, 1, 0)`，方向垂直向上
- 计算右向量 `cross(front, up)` 时全部为零，无法计算左右移动方向
- 这就是**万向锁（Gimbal Lock）**的简化表现形式

## 3. 摄像机自由移动（WASD）

### 3.1 前后移动

```cpp
float velocity = movementSpeed * deltaTime;  // 帧率无关的速度

if (glfwGetKey(window, GLFW_KEY_W) == GLFW_PRESS)
    camPos += velocity * camFront;            // 沿朝向方向前进

if (glfwGetKey(window, GLFW_KEY_S) == GLFW_PRESS)
    camPos -= velocity * camFront;            // 沿朝向反方向后退
```

### 3.2 左右移动（横向平移）

```cpp
if (glfwGetKey(window, GLFW_KEY_A) == GLFW_PRESS)
    // 右向量 = front * up 的叉积，取反得到左移
    camPos -= glm::normalize(glm::cross(camFront, camUp)) * velocity;

if (glfwGetKey(window, GLFW_KEY_D) == GLFW_PRESS)
    // 右移
    camPos += glm::normalize(glm::cross(camFront, camUp)) * velocity;
```

**为什么用叉积？**

```
cross(front, up) = 右向量（Right Vector）
  看向方向        上方向      与两者都垂直的方向

向右 =  cross(front, up)，标准化后乘速度
向左 = -cross(front, up)，标准化后乘速度
```

注意：`camFront` 和 `camUp` 不一定垂直（pitch 变化），叉积结果不一定长度为 1，需要 `glm::normalize`。

### 3.3 没有实现上下移动

FPS 游戏中上下通常指：
- 上：沿世界 Y 轴向上（跳跃）
- 下：沿世界 Y 轴向下（蹲下）

不是沿摄像机自身的 Y 轴，所以这里没有实现 Space/Shift 上下移动。

## 4. 鼠标控制视角

### 4.1 工作流程

```
用户移动鼠标
    |
GLFW 回调进入 mouse_callback(xpos, ypos)
    |
计算鼠标位移量（deltaX, deltaY）
    |
deltaX 变为 yaw 变化（左右看）
deltaY 变为 pitch 变化（上下看，注意 Y 轴翻转）
    |
更新 camFront 向量
```

### 4.2 鼠标位移计算公式

```cpp
void mouse_callback(GLFWwindow* window, double xpos, double ypos)
{
    // 首次进入时跳过跳变
    if (firstMouse)
    {
        lastX = xpos;
        lastY = ypos;
        firstMouse = false;
        return;
    }

    // 计算位移
    float xoffset = xpos - lastX;
    float yoffset = lastY - ypos;  // 翻转！屏幕 Y 向下，世界 Y 向上

    // 应用灵敏度
    xoffset *= sensitivity;
    yoffset *= sensitivity;

    // 更新欧拉角
    yaw   += xoffset;
    pitch += yoffset;

    // 限制 pitch 范围
    if (pitch > 89.0f)  pitch = 89.0f;
    if (pitch < -89.0f) pitch = -89.0f;

    // 更新朝向
    updateCameraFront();

    // 记录当前坐标供下一帧使用
    lastX = xpos;
    lastY = ypos;
}
```

### 4.3 为什么 Y 轴要翻转？

```
屏幕坐标系：          OpenGL 世界坐标系：
(0,0) --- X           Z
  |                    |
  v                    |
  Y               X---+--- Y

屏幕的 Y+ 向下，世界坐标的 Y+ 向上。
鼠标向下移（屏幕 Y+），我们希望视角向上看（Pitch+），
所以 yoffset = lastY - ypos，翻转符号。
```

### 4.4 鼠标捕获机制

```cpp
// 右键点击切换鼠标捕获
if (glfwGetMouseButton(window, GLFW_MOUSE_BUTTON_RIGHT) == GLFW_PRESS)
{
    mouseCaptured = !mouseCaptured;
    glfwSetInputMode(window, GLFW_CURSOR,
        mouseCaptured ? GLFW_CURSOR_DISABLED : GLFW_CURSOR_NORMAL);
    if (mouseCaptured) firstMouse = true;  // 重置，避免跳变
}
```

| 状态 | 鼠标可见 | 可操作 ImGui | 视角控制 |
|------|---------|-------------|---------|
| 释放（默认） | 可见 | 可操作 | 无效 |
| 捕获 | 隐藏 | 无效 | 自由视角 |

**首次鼠标捕获时重置 firstMouse**：防止捕获瞬间鼠标位置跳变导致视角突然转动。

## 5. 滚轮缩放

### 5.1 原理

缩放不是改变摄像机位置。缩放是改变 FOV（Field of View，视野角度）。

```cpp
void scroll_callback(GLFWwindow* window, double xoffset, double yoffset)
{
    fov -= (float)yoffset;
    if (fov < 1.0f)  fov = 1.0f;
    if (fov > 60.0f) fov = 60.0f;
}
```

### 5.2 FOV 变化的效果

| FOV | 效果 | 类比 |
|-----|------|------|
| 大（约 60 度） | 视野广，物体变小 | 广角镜头 |
| 小（约 1 度） | 视野窄，物体放大 | 望远镜 |
| 默认 45 度 | 标准视角 | 人眼等效 |

**本质**：FOV 改变的是透视投影矩阵的参数，不是摄像机位置。

## 6. Delta Time

### 6.1 问题

没有 deltaTime 时，每秒帧数（FPS）变化会导致移动速度变化：

- 60 FPS：每秒移动 60 次乘速度
- 30 FPS：每秒移动 30 次乘速度
- 帧率越低，移动越慢，体验不一致

### 6.2 解决方案

```cpp
// 每帧开始时计算时间差
float currentFrame = glfwGetTime();
deltaTime = currentFrame - lastFrame;
lastFrame = currentFrame;

// 使用 deltaTime 修正移动速度
float velocity = movementSpeed * deltaTime;
camPos += velocity * camFront;
```

**效果**：

- 60 FPS：每帧移动 speed / 60，1 秒累计 speed
- 30 FPS：每帧移动 speed / 30，1 秒累计 speed
- 无论帧率高低，每秒移动的距离相同

## 8. 常见问题

### Q: 为什么视角会突然跳转？

首次捕获鼠标时 `mouse_callback` 立即收到事件，xpos/ypos 可能与初始 lastX/lastY 差距很大，导致大幅视角旋转。

**解决**：`firstMouse` 标记跳过第一次事件，只记录位置不更新视角。

### Q: 为什么左右移动时感觉方向不对？

左右移动用 `cross(front, up)` 计算右向量。如果忘记 `normalize`，pitch 不为 0 时叉积长度不为 1，左右移动速度会不一致。

### Q: 为什么滚轮缩放没有反应？

检查两点：
1. 是否注册了回调：`glfwSetScrollCallback(window, scroll_callback)`
2. 渲染循环中是否用 `glm::radians(fov)` 重建了投影矩阵

### Q: 为什么向下看超过 90 度就乱转了？

超过 89 度的 pitch 会导致 `cos(pitch)` 接近 0，front 向量的 x/z 分量接近零，方向不稳定。这是**万向锁**的体现，用 `clamp(pitch, -89, 89)` 解决。

### Q: 为什么帧率低的时候移动变得卡顿？

帧率低时 deltaTime 变大，每帧移动距离变大，看起来一跳一跳的。这是正常现象，优化渲染性能可以提高帧率。

## 10. 关键知识点总结

### 核心概念

| 概念 | 要点 |
|------|------|
| **摄像机本质** | 视图矩阵的交互式操控，lookAt(pos, pos+front, up) |
| **欧拉角** | Yaw（左右看）加 Pitch（上下看），直观控制朝向 |
| **方向向量** | 球面坐标转笛卡尔，front = (cos(yaw)cos(pitch), sin(pitch), sin(yaw)cos(pitch)) |
| **WASD 移动** | 前后沿 front，左右沿 cross(front, up) |
| **鼠标视角** | 水平位移转 yaw，垂直位移转 pitch，Y 轴需翻转 |
| **滚轮缩放** | 改变 FOV，改变透视投影矩阵 |
| **DeltaTime** | 帧间时间差，实现帧率无关的恒定速度 |
| **万向锁** | pitch 限制 89 度，防止 front 向量坍缩 |
| **鼠标捕获** | GLFW_CURSOR_DISABLED 隐藏并捕获鼠标 |

### 新增 GLFW 回调

| 函数 | 用途 |
|------|------|
| `glfwSetCursorPosCallback(window, callback)` | 注册鼠标移动回调 |
| `glfwSetScrollCallback(window, callback)` | 注册滚轮回调 |
| `glfwSetInputMode(window, GLFW_CURSOR, mode)` | 设置鼠标捕获模式 |
| `glfwGetMouseButton(window, button)` | 查询鼠标按键状态 |
| `glfwGetTime()` | 获取当前时间（秒），用于 deltaTime 计算 |

### 最佳实践

```
摄像机状态集中管理（命名空间或全局变量）：
   方便回调函数访问，结构清晰

deltaTime 帧率无关移动：
   所有帧率下移动速度保持一致

鼠标捕获时重置 firstMouse：
   避免捕获瞬间视角跳变

pitch 限制 89 度：
   防止万向锁和方向向量不稳定

Y 轴翻转：
   屏幕 Y 向下转世界 Y 向上的坐标系转换

每帧重建 view 矩阵：
   确保摄像机状态变化实时反映在画面中
```

### 常见错误

```
yaw 初始化为 0 度
   初始看向 X 正方向，而不是 -Z 方向
   修复：yaw = -90.0f

忘记翻转鼠标 Y 轴
   鼠标向下移时视角也向下，操作反直觉
   修复：yoffset = lastY - ypos

忘记 normalize 右向量
   pitch 不为 0 时左右移动速度异常
   修复：glm::normalize(glm::cross(camFront, camUp))

忘记注册回调
   鼠标移动和滚轮缩放无反应
   修复：glfwSetCursorPosCallback 加 glfwSetScrollCallback

未使用 deltaTime
   高帧率机器上移动飞快，低帧率机器上移动缓慢
   修复：velocity = speed * deltaTime

pitch 限制在 180 度
   视角超过 90 度后上下颠倒，控制混乱
   修复：限制在 89 度

鼠标捕获时忘记重置 firstMouse
   捕获瞬间视角可能跳转
   修复：if (mouseCaptured) firstMouse = true
```
