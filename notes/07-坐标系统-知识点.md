## 1. 五个坐标空间

OpenGL 渲染管线中，顶点经历 5 个坐标空间的变换：

```
局部空间 ──→ 世界空间 ──→ 视图空间 ──→ 裁剪空间 ──→ 屏幕空间
  Local        World        View         Clip         Screen
```

### 1.1 局部空间（Local Space）
- 物体自身的坐标系，原点在物体中心
- 3D 建模软件中创建的顶点就是在局部空间中
- 例如一个立方体的顶点在 `[-0.5, 0.5]` 范围内

### 1.2 世界空间（World Space）
- 所有物体共同存在的虚拟世界坐标系
- 通过**模型矩阵（Model Matrix）**将顶点从局部变换到世界
- 每个物体可以有自己独立的 Model 矩阵

### 1.3 视图空间（View Space）
- 以摄像机为原点的坐标系
- 通过**视图矩阵（View Matrix）**将顶点从世界变换到视图
- 相当于把相机移到原点，所有物体坐标相对变化
- 整个场景共享同一个 View 矩阵

### 1.4 裁剪空间（Clip Space）
- NDC（Normalized Device Coordinates）空间：范围 `[-1, 1]`
- 通过**投影矩阵（Projection Matrix）**将顶点从视图变换到裁剪
- 透视投影产生近大远小效果
- 超出 NDC 范围的顶点被裁剪掉（不可见）

### 1.5 屏幕空间（Screen Space）
- 最终的像素坐标：`[0, width] × [0, height]`
- 由视口变换（Viewport Transform）自动完成
- 对应 `glViewport()` 的设置

## 2. 三大变换矩阵（MVP）

### 2.1 模型矩阵（Model Matrix）

**作用**：将顶点从局部坐标系变换到世界坐标系

**矩阵组合**（先缩放 → 再旋转 → 最后平移）：

```cpp
glm::mat4 model = glm::mat4(1.0f);
model = glm::translate(model, position);  // 3. 平移
model = glm::rotate(model, angle, axis);  // 2. 旋转
model = glm::scale(model, scale);         // 1. 缩放
```

**关键理解**：
- 矩阵乘法从右到左读（先应用右边的矩阵）
- 每个物体有自己的 Model 矩阵 → 同一份 VAO 数据可绘制多个物体
- Model 矩阵每帧变化（驱动动画）

### 2.2 视图矩阵（View Matrix）

**作用**：模拟摄像机，将世界坐标变换到以相机为原点的视图坐标

**生成方式**：`glm::lookAt(eye, center, up)`

```cpp
glm::mat4 view = glm::lookAt(
    glm::vec3(0.0f, 0.0f, 3.0f),   // 相机位置
    glm::vec3(0.0f, 0.0f, 0.0f),   // 观察目标
    glm::vec3(0.0f, 1.0f, 0.0f)    // 向上方向
);
```

**参数含义**：
- `eye`：相机在世界空间中的位置
- `center`：相机看向的目标点
- `up`：定义相机的「上」方向（通常 `(0, 1, 0)`）

### 2.3 投影矩阵（Projection Matrix）

**作用**：将视锥体（Frustum）映射到 NDC `[-1, 1]`

**两种投影方式**：

#### 透视投影（Perspective Projection）
```cpp
glm::mat4 proj = glm::perspective(
    glm::radians(45.0f),          // FOV（视野角度）
    (float)width / (float)height,  // 宽高比
    0.1f,                          // 近平面
    100.0f                         // 远平面
);
```

- **近大远小**，模拟真实人眼效果
- FOV 越大 → 视野越广 → 物体显得越小（鱼眼效果）
- FOV 越小 → 视野越窄 → 物体显得越大（望远镜效果）
- near/far 差距越大 → 深度缓冲精度越低（z-fighting 风险）

#### 正交投影（Orthographic Projection）
```cpp
glm::mat4 proj = glm::ortho(
    0.0f, 800.0f,   // left, right
    0.0f, 600.0f,   // bottom, top
    0.1f, 100.0f    // near, far
);
```

- 物体大小不随距离变化
- 适用于 2D 游戏、CAD、UI

### 2.4 完整 MVP 变换

```glsl
// 顶点着色器中
gl_Position = projection * view * model * vec4(aPos, 1.0);
```

**执行顺序**（从右到左）：
1. `model`：局部 → 世界（每个物体不同）
2. `view`：世界 → 视图（场景共享）
3. `projection`：视图 → 裁剪（场景共享）

**C++ 端设置**：
```cpp
shader.setMat4("projection", proj);   // 不变或偶尔变
shader.setMat4("view", view);          // 相机移动时变
shader.setMat4("model", model);        // 每帧每个物体不同
```

## 3. 深度测试（Z-buffer）

### 3.1 为什么需要深度测试？

没有深度测试时，OpenGL 按照绘制顺序覆盖颜色 → 后绘制的物体总是显示在前面 → 需要手动排序（画家算法）。

深度测试自动解决远近遮挡问题：每个片段写入深度值到 Z-buffer，新片段只有深度值更小（更靠近相机）才通过测试。

### 3.2 启用方式

```cpp
// 初始化时启用
glEnable(GL_DEPTH_TEST);

// 渲染循环中每帧清除深度缓冲
glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT);
```

### 3.3 深度值范围

- NDC 中深度范围 `[-1, 1]` → 映射到深度缓冲 `[0, 1]`
- 近平面 → 深度值 0（靠近相机）
- 远平面 → 深度值 1（远离相机）
- near/far 差距越大 → 精度越低

## 4. 3D 立方体

### 4.1 为什么需要 24 个顶点？

立方体有 8 个角，但每个角属于 3 个面。如果共用顶点，每个面需要不同的纹理坐标 → 一个顶点无法同时拥有 3 组不同的纹理坐标。

**解决方案**：每个面 4 个独立顶点 → 6 × 4 = 24 个顶点 + 36 个索引。

### 4.2 顶点数据组织

```
每个面 4 个顶点，每个顶点 5 个 float（position 3 + texcoord 2）
总数据量：24 × 5 = 120 个 float = 480 字节

索引缓冲：36 个 unsigned int = 144 字节
总共上传到 GPU：624 字节
```

### 4.3 顶点属性设置

```cpp
// 位置属性 (location = 0) —— vec3
glVertexAttribPointer(0, 3, GL_FLOAT, GL_FALSE, 5 * sizeof(float), (void*)0);
glEnableVertexAttribArray(0);

// 纹理坐标属性 (location = 1) —— vec2
glVertexAttribPointer(1, 2, GL_FLOAT, GL_FALSE, 5 * sizeof(float), (void*)(3 * sizeof(float)));
glEnableVertexAttribArray(1);
```

## 5. 十个立方体阵列

### 5.1 核心思想：数据复用

同一个 VAO（24 个顶点 + 36 个索引），通过 10 个不同的 Model 矩阵，绘制 10 个不同位置的立方体。

```cpp
for (int i = 0; i < 10; i++)
{
    glm::mat4 model = glm::mat4(1.0f);
    model = glm::translate(model, cubePositions[i]);
    model = glm::rotate(model, angle, axis);
    shader.setMat4("model", model);
    glDrawElements(GL_TRIANGLES, 36, GL_UNSIGNED_INT, 0);
}
```

**性能优势**：CPU 只需上传 10 × 16 个 float = 640 字节的矩阵数据，GPU 复用同一份顶点数据绘制 10 次。

| 键盘 | `1` `2` `3` | 切换 1/2/3 模式 |
| 键盘 | 空格 | 切换线框/填充 |
| 键盘 | `Tab` | 显示/隐藏 ImGui 面板 |

### 5.3 三种显示模式

## 6. 代码亮点

### 6.1 Shader 类新增 setMat4

```cpp
void setMat4(const std::string& name, const glm::mat4& mat) const
{
    glUniformMatrix4fv(glGetUniformLocation(ID, name.c_str()), 1, GL_FALSE, glm::value_ptr(mat));
}
```

注意 `GL_FALSE`：GLM 使用列主序（Column-major），OpenGL 也使用列主序，所以不需要转置。

### 6.2 线框模式

```cpp
glPolygonMode(GL_FRONT_AND_BACK, GL_LINE);  // 线框
glPolygonMode(GL_FRONT_AND_BACK, GL_FILL);  // 填充（默认）
```

线框模式可以清晰观察立方体的 3D 结构和顶点连接关系，是调试 3D 场景的常用手段。

### 6.3 ImGui 调试面板

ImGui 面板集成在 `coordinates_main.cpp` 中，提供以下调试功能：

| 控件 | 功能 |
|------|------|
| FPS 显示 | 实时帧率与帧耗时 |
| RadioButton (1/2/3) | 切换显示模式 |
| Wireframe 复选框 | 开关线框模式 |

### 6.4 相机移动控制

通过**键盘** 或 **ImGui 滑条** 控制相机位置：

| 控制方式 | 操作 | 效果 |
|----------|------|------|
| `←` / `A` 或 X 滑条 | 相机左移 | 场景右移 |
| `→` / `D` 或 X 滑条 | 相机右移 | 场景左移 |
| `↑` / `W` 或 Y 滑条 | 相机上移 | 场景下移 |
| `↓` / `S` 或 Y 滑条 | 相机下移 | 场景上移 |

原理：每帧用全局变量 `g_camPosX` / `g_camPosY` / `g_camDistance` 重建 `glm::lookAt` 矩阵。

```cpp
// 每帧重建视图矩阵（允许实时调整）
glm::mat4 view = glm::lookAt(
    glm::vec3(g_camPosX, g_camPosY, g_camDistance),  // 动态相机位置
    glm::vec3(g_camPosX, g_camPosY, 0.0f),            // 目光始终向前
    glm::vec3(0.0f, 1.0f, 0.0f)                       // Y 轴向上
);
```

## 7. 常见问题

### Q: 为什么立方体看起来是平的？
A: 忘记启用深度测试（`glEnable(GL_DEPTH_TEST)`）或忘记清除深度缓冲（`glClear(GL_DEPTH_BUFFER_BIT)`）。

### Q: 为什么立方体变形？
A: 投影矩阵的宽高比与窗口宽高比不匹配。确保 `aspectRatio = width / height` 是正确的。

### Q: 为什么画面闪烁（深度冲突/Z-fighting）？
A: near 和 far 平面差距太大，深度缓冲精度不够。建议适当缩小差距（如 near=0.1, far=100）。

### Q: 为什么纹理贴图不对？
A: 立方体每个面需要独立的纹理坐标。检查你的顶点数据，确保每个面的 4 个顶点的纹理坐标正确覆盖了 `[0, 1]`。

## 9. 关键知识点总结

### 🎯 核心概念

| 概念 | 要点 |
|------|------|
| **五个坐标空间** | 局部 → 世界 → 视图 → 裁剪 → 屏幕 |
| **MVP 矩阵** | Model（局部→世界）× View（世界→视图）× Projection（视图→裁剪） |
| **Model 矩阵** | 每个物体独立，驱动位置/旋转/缩放 |
| **View 矩阵** | `glm::lookAt` 生成，场景共享 |
| **Projection 矩阵** | 透视（近大远小）或正交（不变大小） |
| **深度测试** | `glEnable(GL_DEPTH_TEST)` 解决遮挡问题 |
| **24 顶点立方体** | 每个面 4 个独立顶点（因纹理坐标不共享） |
| **数据复用** | 同一 VAO + 不同 Model 矩阵 → 多物体绘制 |

### 📦 新增函数

| 函数/API | 用途 |
|----------|------|
| `glm::lookAt(eye, center, up)` | 生成视图矩阵 |
| `glm::perspective(fov, ratio, near, far)` | 生成透视投影矩阵 |
| `glm::ortho(left, right, bottom, top, near, far)` | 生成正交投影矩阵 |
| `glUniformMatrix4fv(loc, 1, GL_FALSE, ptr)` | 上传 mat4 到 uniform（已封装在 setMat4 中） |
| `glEnable(GL_DEPTH_TEST)` | 启用深度测试 |
| `glClear(GL_DEPTH_BUFFER_BIT)` | 清除深度缓冲 |
| `glPolygonMode(GL_FRONT_AND_BACK, GL_LINE)` | 线框模式 |

### 💡 最佳实践

```
MVP 矩阵顺序（顶点着色器）：
gl_Position = projection * view * model * vec4(aPos, 1.0);

Model 矩阵构建顺序（TRS）：
model = translate(rotate(scale(identity, s), angle, axis), pos)

深度测试：
启用后必须在每帧清除深度缓冲，否则上一帧的深度残留导致绘制错误

视口匹配：
投影矩阵的宽高比必须与 glViewport 设置的窗口大小一致

每帧更新：
View 和 Model 矩阵通常每帧重新计算，Projection 矩阵仅在窗口大小变化或 FOV 调整时更新
```

### ⚠️ 常见错误

```
❌ 忘记启用深度测试
   → 立方体看起来是平的，后绘制的面覆盖先绘制的
   ✅ 修复：在初始化中加入 glEnable(GL_DEPTH_TEST)

❌ 忘记清除深度缓冲
   → 每帧深度值累加，新绘制的物体不可见
   ✅ 修复：glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT)

❌ MVP 顺序写反
   gl_Position = model * view * projection * vec4(aPos, 1.0);
   → 先应用投影变换，但此时顶点还在局部空间，结果完全错误
   ✅ 修复：gl_Position = projection * view * model * vec4(aPos, 1.0)

❌ 投影矩阵宽高比与窗口不匹配
   → 立方体被拉伸变形
   ✅ 修复：确保 aspect = width / height 是实时正确的

❌ 误用正交投影
   → 3D 场景看起来是平的（无近大远小效果）
   ✅ 修复：3D 场景用 glm::perspective，2D 场景才用 glm::ortho

❌ near/far 差距过大导致 z-fighting
   → 远处物体闪烁，深度冲突
   ✅ 修复：near=0.1, far=100 已足够大多数场景
```
