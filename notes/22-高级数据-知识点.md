## 1. 概述

**高级数据（Advanced Data）** 是高级 OpenGL 第七章。前面所有章节只用过 `glBufferData` 一次性填充整个缓冲区，本章介绍更灵活的缓冲区管理方式。

### 1.1 四种核心技术

| 技术 | 用途 |
|------|------|
| **glBufferSubData** | 填充缓冲区的**特定区域**（偏移 + 大小），而非整个缓冲区 |
| **glMapBuffer** | 获取 GPU 缓冲区内存的 **CPU 指针**，直接读写 |
| **分批布局** | 将所有顶点的同类属性打包在一起（位置在前、颜色在后） |
| **glCopyBufferSubData** | 在**两个缓冲区之间**复制数据 |

### 1.2 核心思路

```
glBufferData      →  一次性填满整个 VBO
glBufferSubData   →  分多次填不同的区域
glMapBuffer       →  拿指针直接写（无需中间数组）
glCopyBufferSubData →  VBO → VBO 复制

三者配合使用，可以实现灵活高效的缓冲区管理。
```

## 2. glBufferSubData — 填充缓冲区特定区域

### 2.1 函数原型

```cpp
void glBufferSubData(GLenum target, GLintptr offset, GLsizeiptr size, const void* data);
```

| 参数 | 说明 |
|------|------|
| `target` | 缓冲目标（如 `GL_ARRAY_BUFFER`） |
| `offset` | 写入起始偏移（**字节**） |
| `size` | 写入数据大小（**字节**） |
| `data` | 数据指针 |

### 2.2 关键前提

**必须先调用 `glBufferData` 分配足够内存**，然后才能用 `glBufferSubData` 更新：

```cpp
// ★ 第一步：分配内存（data = NULL 表示只分配，不填充）
glBufferData(GL_ARRAY_BUFFER, totalSize, NULL, GL_STATIC_DRAW);

// ★ 第二步：用 glBufferSubData 分别填入不同区域
glBufferSubData(GL_ARRAY_BUFFER, 0,            posSize, positions);   // 位置 → offset 0
glBufferSubData(GL_ARRAY_BUFFER, posSize,      colSize, colors);     // 颜色 → offset = posSize
```

### 2.3 与 glBufferData 对比

| | glBufferData | glBufferSubData |
|---|---|---|
| 作用范围 | 整个缓冲区 | 缓冲区的一部分 |
| 是否分配内存 | 是 | 否（需要预先分配） |
| 使用场景 | 一次性填充、静态数据 | 分步填充、动态更新部分数据 |
| `data=NULL` | 只分配，不填充 | N/A |

## 3. glMapBuffer — 直接内存映射

### 3.1 原理

`glMapBuffer` 返回 GPU 缓冲区内存的 **CPU 可访问指针**，允许直接读写缓冲区数据，无需通过中间数组中转。

### 3.2 函数原型

```cpp
void* glMapBuffer(GLenum target, GLenum access);
GLboolean glUnmapBuffer(GLenum target);
```

| 参数 | 说明 |
|------|------|
| `target` | 缓冲目标 |
| `access` | `GL_READ_ONLY` / `GL_WRITE_ONLY` / `GL_READ_WRITE` |
| 返回值 | 指向缓冲区内存的指针，失败返回 `NULL` |

### 3.3 使用示例

```cpp
glBindBuffer(GL_ARRAY_BUFFER, vbo);

// ★ 获取 GPU 缓冲区的 CPU 可写指针
float* mapped = (float*)glMapBuffer(GL_ARRAY_BUFFER, GL_WRITE_ONLY);

if (mapped)
{
    // 直接修改缓冲区内容（无需临时数组！）
    for (int i = 0; i < numVertices; i++) {
        mapped[i * 6 + 0] = positions[i * 6 + 0] * scale;  // 修改位置
        mapped[i * 6 + 1] = positions[i * 6 + 1] * scale;
        mapped[i * 6 + 2] = positions[i * 6 + 2] * scale;
        // 颜色保持不变 …
    }

    // ★ 通知 OpenGL 数据写入完成
    //   返回 GL_TRUE 表示成功
    glUnmapBuffer(GL_ARRAY_BUFFER);
}
```

### 3.4 适用场景

- **顶点动画**：每帧修改顶点位置（呼吸、波浪、变形）
- **从文件流式读取**：直接将文件数据复制到 GPU 缓冲区，无需临时数组
- **动态粒子系统**：频繁更新粒子位置

### 3.5 注意事项

- `glMapBuffer` 期间不要对该缓冲区做其他 GL 操作
- 记得调用 `glUnmapBuffer`，否则数据可能未真正写入
- `glUnmapBuffer` 返回 `GL_FALSE` 表示写入失败（如 GPU 内存不足）

## 4. 分批顶点属性（Batched Attributes）

### 4.1 两种布局对比

**交错布局（Interleaved）** — 每个顶点的属性紧密排列：

```
| pos0 | col0 | pos1 | col1 | pos2 | col2 | ... |
```

- stride = 6 × sizeof(float) = 24 bytes
- position offset = 0, color offset = 12

**分批布局（Batched）** — 同类属性打包在一起：

```
| pos0 | pos1 | pos2 | ... | posN | col0 | col1 | col2 | ... | colN |
```

- position stride = 3 × sizeof(float) = 12 bytes（同类属性连续）
- color stride = 3 × sizeof(float) = 12 bytes
- color offset = positions 的总大小

### 4.2 分批布局的代码

```cpp
float positions[] = { /* 所有顶点的位置 */ };
float colors[]    = { /* 所有顶点的颜色 */ };

// 1. 分配内存
glBufferData(GL_ARRAY_BUFFER, totalSize, NULL, GL_STATIC_DRAW);

// 2. 填入位置和颜色
glBufferSubData(GL_ARRAY_BUFFER, 0,        sizeof(positions), positions);
glBufferSubData(GL_ARRAY_BUFFER, sizeof(positions), sizeof(colors), colors);

// 3. 设置属性指针
glVertexAttribPointer(0, 3, GL_FLOAT, GL_FALSE, 3 * sizeof(float), (void*)0);
glVertexAttribPointer(1, 3, GL_FLOAT, GL_FALSE, 3 * sizeof(float),
                      (void*)sizeof(positions));
```

### 4.3 交错 vs 分批 — 选择建议

| | 交错布局 | 分批布局 |
|---|---|---|
| **缓存命中率** | ⭐⭐⭐ 更高（顶点数据局部性好） | ⭐⭐ 较低 |
| **代码整洁度** | ⭐⭐ | ⭐⭐⭐（同类数据集中） |
| **部分更新** | 困难（需要跳过颜色） | 容易（直接更新位置区域） |
| **官方推荐** | ✅ **推荐**（缓存效率高） | 特定场景 |

> ⚠️ **教程建议**：优先使用交错布局。虽然分批方式代码更整洁，但交错布局让顶点着色器运行时所需的数据在内存中更紧密，缓存命中率更高。

## 5. glCopyBufferSubData — 缓冲区复制

### 5.1 函数原型

```cpp
void glCopyBufferSubData(GLenum readTarget, GLenum writeTarget,
                         GLintptr readOffset, GLintptr writeOffset,
                         GLsizeiptr size);
```

| 参数 | 说明 |
|------|------|
| `readTarget` | 源缓冲目标 |
| `writeTarget` | 目标缓冲目标 |
| `readOffset` | 源缓冲区读取偏移（字节） |
| `writeOffset` | 目标缓冲区写入偏移（字节） |
| `size` | 复制数据大小（字节） |

### 5.2 核心问题与解决

**问题**：两个 VBO 不能同时绑定到同一个 `GL_ARRAY_BUFFER` 目标。

**解决**：OpenGL 提供了两个专用目标：
- `GL_COPY_READ_BUFFER` — 复制源
- `GL_COPY_WRITE_BUFFER` — 复制目标

```cpp
// ★ 两个 VBO 之间的复制
glBindBuffer(GL_COPY_READ_BUFFER, vboA);
glBindBuffer(GL_COPY_WRITE_BUFFER, vboC);
glCopyBufferSubData(GL_COPY_READ_BUFFER, GL_COPY_WRITE_BUFFER,
                    0, 0, dataSize);

// 恢复绑定，避免影响后续操作
glBindBuffer(GL_COPY_READ_BUFFER, 0);
glBindBuffer(GL_COPY_WRITE_BUFFER, 0);
```

### 5.3 也可以只绑定写入目标

如果源和目标类型不同（比如 VBO → UBO），可以只把写入目标绑定到专用目标：

```cpp
glBindBuffer(GL_ARRAY_BUFFER, vboA);               // 源：普通 VBO 绑定
glBindBuffer(GL_COPY_WRITE_BUFFER, vboC);           // 目标：专用复制目标
glCopyBufferSubData(GL_ARRAY_BUFFER, GL_COPY_WRITE_BUFFER, 0, 0, dataSize);
```

### 5.4 适用场景

- 将静态几何体复制到动态缓冲区作为初始状态
- 在不同类型的缓冲区之间转移数据（VBO → UBO、VBO → PBO 等）
- 备份/恢复缓冲区内容

## 7. 关键知识点总结

### 7.1 API 速查表

| API | 作用 | 关键参数 |
|-----|------|---------|
| `glBufferData(target, size, data, usage)` | 分配 + 填充整个缓冲区 | `data=NULL` 只分配不填充 |
| `glBufferSubData(target, offset, size, data)` | 填充缓冲区的一部分 | offset 必须是已分配范围内的偏移 |
| `glMapBuffer(target, access)` | 获取 GPU 缓冲区指针 | 返回 `NULL` 表示失败 |
| `glUnmapBuffer(target)` | 通知 OpenGL 写入完成 | 返回 `GL_FALSE` 表示失败 |
| `glCopyBufferSubData(rt, wt, ro, wo, sz)` | 缓冲区之间复制 | 使用 `GL_COPY_READ/WRITE_BUFFER` 目标 |

### 7.2 使用场景总结

| 场景 | 推荐技术 |
|------|---------|
| 静态几何体（加载后不变） | `glBufferData` 一次性填充 |
| 已知大小的动态数据 | `glBufferData(NULL)` + `glBufferSubData` |
| 每帧更新所有顶点 | `glMapBuffer`（避免额外副本） |
| 从文件流式加载 | `glMapBuffer` + `memcpy` |
| VBO 间复制 | `glCopyBufferSubData` |

### 7.3 缓冲区使用提示

| 提示 | 说明 |
|------|------|
| `GL_STATIC_DRAW` | 数据设置一次，使用多次 |
| `GL_DYNAMIC_DRAW` | 数据频繁修改，使用多次 |
| `GL_STREAM_DRAW` | 数据每次绘制都不同 |
| 交错布局优先 | 缓存命中率更高（官方推荐） |
