## 1. 概述

**模板测试（Stencil Testing）** 是 OpenGL 高级部分的第二章（紧接深度测试），它提供了一种**基于像素形状**的片段丢弃机制。

### 1.1 为什么需要模板测试？

| 场景 | 不用模板测试 | 用模板测试 |
|------|-------------|-----------|
| 物体描边 | 难以在已绘制物体周围画出均匀边框 | 两步渲染轻松实现 |
| 镜面反射 | 无法限制反射内容只在镜面内 | 标记镜面区域 → 只在该区域内渲染 |
| 阴影体积 | 无法精确计算阴影边界 | Stencil Buffer 累加/递减计数 |
| 平面裁剪 | 复杂的裁剪面计算 | Stencil 标记裁剪区域 |

### 1.2 渲染管线中的位置

```
顶点着色器 → 几何着色器 → 光栅化 → 片段着色器 → 模板测试 → 深度测试 → 混合 → 帧缓冲
                                                    ↑              ↑
                                                 模板缓冲区      深度缓冲区
```

**模板测试** 发生在**片段着色器之后、深度测试之前**。如果一个片段没有通过模板测试，它会被立即丢弃，不会进入深度测试阶段。

### 1.3 为什么本章在深度测试之后？

深度测试 和 模板测试 是 **同一管线阶段** 的两个测试，它们配合工作：

- 深度测试：决定片段的"前后"关系
- 模板测试：决定片段的"区域"限制

理解深度测试之后再来学习模板测试，可以更好地理解两者的配合。

## 2. 模板缓冲区（Stencil Buffer）

### 2.1 核心概念

- 模板缓冲区是一个与颜色缓冲区分辨率相同的 **二维整型数组**
- 每个像素通常 **8 位**（0 ~ 255，共 256 种不同的模板值）
- 模板缓冲区不直接显示在屏幕上，但对渲染管线有"过滤"作用
- GLFW 默认**不分配**模板缓冲区，需要手动请求

### 2.2 请求模板缓冲区

```cpp
// ★ 创建窗口前必须设置此 Hint
glfwWindowHint(GLFW_STENCIL_BITS, 8);

GLFWwindow* window = glfwCreateWindow(800, 600, "Window", NULL, NULL);
```

### 2.3 清空模板缓冲区

```cpp
// 设置清屏用的模板值（默认 0）
glClearStencil(0);

// ★ 每帧清空颜色、深度、模板三个缓冲区
glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT | GL_STENCIL_BUFFER_BIT);
```

### 2.4 启用模板测试

```cpp
glEnable(GL_STENCIL_TEST);
// 默认状态：
//   glStencilFunc(GL_ALWAYS, 0, 0xFF)   → 始终通过，参考值=0
//   glStencilOp(GL_KEEP, GL_KEEP, GL_KEEP) → 不修改模板值
//   glStencilMask(0xFF)                   → 允许写入所有位
```

## 3. 模板测试函数（glStencilFunc）

### 3.1 函数签名

```cpp
void glStencilFunc(GLenum func, GLint ref, GLuint mask);
```

### 3.2 参数详解

| 参数 | 类型 | 说明 |
|------|------|------|
| `func` | GLenum | 模板测试的比较函数 |
| `ref` | GLint | 参考值（0~255），与模板缓冲区中的值比较 |
| `mask` | GLuint | 位掩码，与 ref 和模板值都做 AND 运算后再比较 |

### 3.3 工作原理

```
实际比较 = (模板缓冲区值 & mask) 与 (ref & mask)

如果 func(实际比较) == true  → 片段通过模板测试
如果 func(实际比较) == false → 片段被丢弃
```

### 3.4 比较函数一览

| func 值 | 含义 | 通过条件 |
|---------|------|---------|
| `GL_ALWAYS` | 始终通过 | 无条件 |
| `GL_NEVER` | 永不通过 | 无条件丢弃 |
| `GL_LESS` | 小于 | 模板值 < ref |
| `GL_LEQUAL` | 小于等于 | 模板值 ≤ ref |
| `GL_GREATER` | 大于 | 模板值 > ref |
| `GL_GEQUAL` | 大于等于 | 模板值 ≥ ref |
| `GL_EQUAL` | 等于 | 模板值 = ref |
| `GL_NOTEQUAL` | 不等于 | 模板值 ≠ ref |

### 3.5 mask 的作用

`mask` 参数是 **位级别的过滤**：

```cpp
// 假设模板值是 0b11001010 (202)

glStencilFunc(GL_EQUAL, 1, 0xFF);  // 检查所有 8 位：202 ≠ 1 → 不通过
glStencilFunc(GL_EQUAL, 1, 0x01);  // 只检查最低位：202 & 1 = 0, 1 & 1 = 1, 0 ≠ 1 → 不通过
glStencilFunc(GL_EQUAL, 0, 0x01);  // 检查最低位：202 & 1 = 0, 0 & 1 = 0, 0 = 0 → 通过！
```

常用写法：`mask = 0xFF` 表示使用全部 8 位（不忽略任何位）。

## 4. 模板操作（glStencilOp）

### 4.1 函数签名

```cpp
void glStencilOp(GLenum sfail, GLenum dpfail, GLenum dppass);
```

### 4.2 参数详解

三个参数分别对应三种测试结果场景：

| 参数 | 触发条件 | 直白理解 |
|------|---------|---------|
| `sfail` | **模板测试失败** | 片段被丢弃，但模板值如何处理？ |
| `dpfail` | 模板通过，但 **深度测试失败** | 片段被深度遮挡，模板值如何处理？ |
| `dppass` | 模板通过 + 深度通过 | 片段最终可见，模板值如何处理？ |

### 4.3 动作一览

| 动作 | 效果 |
|------|------|
| `GL_KEEP` | 保持模板值不变（不修改） |
| `GL_ZERO` | 将模板值设为 0 |
| `GL_REPLACE` | 用 glStencilFunc 中的 ref 值替换 |
| `GL_INCR` | 模板值 +1（上限固定在 255，不溢出） |
| `GL_INCR_WRAP` | 模板值 +1（溢出时回绕到 0） |
| `GL_DECR` | 模板值 -1（下限固定在 0，不溢出） |
| `GL_DECR_WRAP` | 模板值 -1（溢出时回绕到 255） |
| `GL_INVERT` | 按位取反 |

### 4.4 典型用法

```cpp
// Palss 1: 标记物体区域 → 写入 ref 值
glStencilFunc(GL_ALWAYS, 1, 0xFF);     // 始终通过，ref=1
glStencilOp(GL_KEEP, GL_KEEP, GL_REPLACE);  // 深度通过时，用 ref=1 替换

// Pass 2: 描边 → 只在物体区域外绘制
glStencilFunc(GL_NOTEQUAL, 1, 0xFF);   // 模板值 ≠ 1 才通过
glStencilOp(GL_KEEP, GL_KEEP, GL_KEEP); // 不修改模板值
```

## 5. 模板写入掩码（glStencilMask）

### 5.1 函数签名

```cpp
void glStencilMask(GLuint mask);
```

### 5.2 作用

控制向模板缓冲区**写入**时的位掩码：

| mask 值 | 效果 |
|---------|------|
| `0xFF` | 允许写入全部 8 位（默认） |
| `0x00` | **禁止写入**（只读模式） |
| `0x01` | 只允许最低位写入 |

### 5.3 注意事项

- `glStencilMask` 只影响 **写入**，不影响 **读取** 和 **比较**
- `glStencilFunc` 中的 mask 只影响 **比较** 时的位过滤
- 两者互不干涉

## 6. 经典应用：物体描边（Object Outlining）

这是模板测试最经典、最直观的应用，类似于建模软件中选中物体的高亮边框。

### 6.1 原理

**三步走策略**：

```
Pass 1: 绘制场景（地板等不参与描边的物体）
  ┌─────────────────────────────────┐
  │  stencilMask: 0x00 (禁止写)     │
  │  正常着色，不修改模板缓冲区       │
  └─────────────────────────────────┘

Pass 2: 绘制物体（正常渲染 + 标记模板）
  ┌─────────────────────────────────┐
  │  stencilFunc: GL_ALWAYS, ref=1  │
  │  stencilOp: GL_REPLACE          │
  │  stencilMask: 0xFF (允许写)     │
  │  → 物体覆盖的像素：模板值设为 1  │
  │  → 其他像素：模板值保持 0        │
  └─────────────────────────────────┘

Pass 3: 绘制描边（放大物体 + 纯色 + 排除已标记区域）
  ┌─────────────────────────────────┐
  │  stencilFunc: GL_NOTEQUAL, ref=1│
  │  stencilOp: GL_KEEP             │
  │  stencilMask: 0x00 (禁止写)     │
  │  glDisable(GL_DEPTH_TEST)       │
  │  放大物体模型矩阵 (×1.05)       │
  │  纯色着色器                     │
  │  → 放大部分超出原物体的区域     │
  │    模板值为 0 → 通过 → 被绘制   │
  │  → 原物体区域模板值为 1         │
  │    → 不通过 → 不被绘制           │
  │  → 结果：只有边框可见           │
  └─────────────────────────────────┘
```

### 6.2 图解

```
原始物体（Pass 2 标记为 1）：
  ┌─────────┐
  │  stencil │
  │   = 1    │   ← 物体覆盖的像素
  │          │
  └─────────┘

放大物体（Pass 3，排除 stencil=1）：
  ┌─────────────┐
  │  ▓▓▓▓▓▓▓▓▓  │
  │  ▓┌───────┐▓ │
  │  ▓│       │▓ │  ▓ = 描边框（stencil=0 → 通过测试）
  │  ▓│       │▓ │  ┌─┘ = 原物体区域（stencil=1 → 不通过）
  │  ▓└───────┘▓ │
  │  ▓▓▓▓▓▓▓▓▓  │
  └─────────────┘
```

### 6.3 完整代码流程

```cpp
// ===== 清空三个缓冲区 =====
glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT | GL_STENCIL_BUFFER_BIT);

// ===== Pass 1: 地板（不写模板） =====
glStencilMask(0x00);  // 禁止写模板
shader.use();
DrawFloor();

// ===== Pass 2: 物体（正常渲染 + 写模板=1） =====
glStencilFunc(GL_ALWAYS, 1, 0xFF);       // 始终通过，ref=1
glStencilOp(GL_KEEP, GL_KEEP, GL_REPLACE); // 深度通过 → 写1
glStencilMask(0xFF);                      // 允许写
shader.use();
DrawContainers();  // 此时物体覆盖的像素模板值=1

// ===== Pass 3: 描边（放大 + 纯色 + 排除模板=1） =====
glStencilFunc(GL_NOTEQUAL, 1, 0xFF);      // 模板≠1 才通过
glStencilOp(GL_KEEP, GL_KEEP, GL_KEEP);   // 不修改模板
glStencilMask(0x00);                      // 禁止写
glDisable(GL_DEPTH_TEST);                 // 描边不应被遮挡

outlineShader.use();
outlineShader.setVec3("outlineColor", glm::vec3(1.0f, 1.0f, 0.0f));

for (auto& cube : cubes) {
    // ★ 放大：在局部空间缩放
    glm::mat4 model = glm::translate(glm::mat4(1.0f), cube.pos);
    model = glm::rotate(model, angle, axis);
    model = glm::scale(model, glm::vec3(1.05f));  // 放大 5%
    outlineShader.setMat4("model", model);
    glDrawElements(GL_TRIANGLES, 36, GL_UNSIGNED_INT, 0);
}

// ===== 恢复状态 =====
glEnable(GL_DEPTH_TEST);
glStencilFunc(GL_ALWAYS, 0, 0xFF);
glStencilMask(0xFF);
```

### 6.4 描边宽度控制

描边宽度通过 **放大倍数** 控制：

```
outlineScale = 0.05  → 物体放大 5%  → 窄边框
outlineScale = 0.10  → 物体放大 10% → 中等边框
outlineScale = 0.20  → 物体放大 20% → 粗边框

缩放方式：model = translate * rotate * scale(1.0 + outlineScale)
在局部空间缩放保证了边框均匀，不受世界位置影响。
```

### 6.5 关键细节

| 细节 | 为什么重要 |
|------|-----------|
| Pass 3 禁用深度测试 | 描边应始终可见，即使被其他物体遮挡 |
| Pass 3 禁止写模板 | 描边只是视觉效果，不应改变模板状态 |
| 在局部空间缩放 | 保证边框均匀，不会因为物体在世界空间的位置而变形 |
| 统一使用 `mask=0xFF` | 使用全部 8 位，避免位过滤导致的意外 |

## 7. Stencil Buffer 的其他应用

除了物体描边，模板测试还有以下经典应用：

### 7.1 镜面反射（Mirror Reflection）

| 步骤 | 操作 |
|------|------|
| 1 | 将镜面区域的模板值设为 1 |
| 2 | 只在模板值=1 的区域渲染反射内容 |
| 3 | 反射内容不会"溢出"到镜面外 |

### 7.2 阴影体积（Shadow Volume）

使用模板缓冲的 INCR/DECR 操作计算阴影边界：

- 正面通过 → INCR（模板值+1）
- 背面通过 → DECR（模板值-1）
- 模板值 ≠ 0 的像素在阴影中

### 7.3 平面裁剪（Planar Clipping）

- 标记裁剪区域 → 只在该区域内渲染

### 7.4 贴花（Decal）

- 在物体表面贴纹理时，用模板缓冲防止重复绘制

## 9. 关键知识点总结

### 9.1 核心 API 速查

```cpp
// 1. 请求模板缓冲区（创建窗口前）
glfwWindowHint(GLFW_STENCIL_BITS, 8);

// 2. 启用模板测试
glEnable(GL_STENCIL_TEST);

// 3. 设置比较函数：什么条件下片段通过模板测试
glStencilFunc(func, ref, mask);
//   func: GL_ALWAYS, GL_EQUAL, GL_NOTEQUAL, GL_LESS, ...
//   ref:  参考值 (0~255)
//   mask: 位掩码 (通常 0xFF)

// 4. 设置动作：测试结果如何影响模板值
glStencilOp(sfail, dpfail, dppass);
//   GL_KEEP, GL_ZERO, GL_REPLACE, GL_INCR, GL_DECR, GL_INVERT

// 5. 控制写入权限
glStencilMask(mask);
//   0xFF = 允许写入所有位
//   0x00 = 完全禁止写入

// 6. 清空模板缓冲区
glClear(GL_STENCIL_BUFFER_BIT);
```

### 9.2 物体描边三步法

```
Step 1: 不写模板，正常绘制场景
Step 2: 写模板=1，绘制要描边的物体
Step 3: 排除模板=1，纯色绘制放大的物体 → 只有边框显示
```

### 9.3 与深度测试的对比

| | 深度测试 | 模板测试 |
|---|---------|---------|
| 决定什么 | 片段的前后关系 | 片段的区域限制 |
| 缓冲区值 | 浮点数（非线性） | 整数（0~255） |
| 默认值 | 1.0（最远） | 0 |
| 典型应用 | 正常 3D 渲染 | 描边、镜面、阴影 |
| 默认行为 | GL_LESS（更近的覆盖） | GL_ALWAYS（始终通过） |
