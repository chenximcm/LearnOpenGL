## 1. 概述

**帧缓冲（Framebuffer）** 是 OpenGL 高级部分第五章。前面所有章节的渲染结果都直接输出到**默认帧缓冲**（屏幕），而本章教你创建**自定义帧缓冲**，将场景渲染到纹理上，然后用该纹理做后处理。

### 1.1 为什么需要自定义帧缓冲？

| 需求 | 默认帧缓冲 | 自定义帧缓冲 |
|------|-----------|-------------|
| 渲染到屏幕 | ✓ | 需要额外步骤 |
| 渲染到纹理 | ✗ | ✓ |
| 后处理效果 | ✗ | ✓ |
| 延迟渲染 | ✗ | ✓ |
| 阴影映射 | ✗ | ✓ |
| 镜面反射 | ✗ | ✓ |

### 1.2 核心思路

```
第一遍：绑定 FBO → 渲染场景 → 场景画面写入 FBO 的颜色纹理
第二遍：绑定默认帧缓冲 → 画全屏四边形 → 采样 FBO 纹理 → 应用后处理着色器
```

### 1.3 在管线中的位置

```
片段着色器 → 模板测试 → 深度测试 → 混合 → 帧缓冲
                                              ↑
                                    所有结果最终写入这里
```

帧缓冲是管线的**最终目的地**。所有测试和混合的结果都写入当前绑定的帧缓冲。

## 2. 帧缓冲的构成

一个完整的帧缓冲由**附件（Attachment）** 组成：

```
┌─────────────────────────────────────┐
│           Frame Buffer              │
│                                     │
│  ┌─────────────────────────────┐    │
│  │  颜色附件 (Color Attachment) │    │
│  │  可以是纹理 或 RBO          │    │
│  └─────────────────────────────┘    │
│  ┌─────────────────────────────┐    │
│  │  深度附件 (Depth Attachment) │    │
│  │  可以是纹理 或 RBO          │    │
│  └─────────────────────────────┘    │
│  ┌─────────────────────────────┐    │
│  │  模板附件 (Stencil Attachment)│   │
│  │  可以是纹理 或 RBO          │    │
│  └─────────────────────────────┘    │
└─────────────────────────────────────┘
```

### 2.1 附件类型

| 附件 | 用途 | 常用形式 |
|------|------|---------|
| `GL_COLOR_ATTACHMENT0` ~ 31 | 存储颜色数据 | 纹理（需要采样时） |
| `GL_DEPTH_ATTACHMENT` | 存储深度数据 | RBO（不需采样时） |
| `GL_STENCIL_ATTACHMENT` | 存储模板数据 | RBO（不需采样时） |
| `GL_DEPTH_STENCIL_ATTACHMENT` | 深度+模板合二为一 | RBO（更高效） |

### 2.2 纹理 vs 渲染缓冲对象（RBO）

| 特性 | 纹理 | RBO |
|------|------|-----|
| 能否在着色器中采样？ | ✓ 可以 | ✗ 不可以 |
| 写入性能 | 较慢 | 较快（GPU 内部格式） |
| 适用场景 | 需要后处理（采样） | 只写不读（深度/模板） |

**经验法则**：需要采样的附件用纹理（颜色附件），不需要采样的用 RBO（深度/模板）。

## 3. 创建帧缓冲（FBO）

### 3.1 完整创建流程

```cpp
// 1. 创建 FBO
unsigned int fbo;
glGenFramebuffers(1, &fbo);
glBindFramebuffer(GL_FRAMEBUFFER, fbo);

// 2. 创建颜色纹理附件
unsigned int texColorBuffer;
glGenTextures(1, &texColorBuffer);
glBindTexture(GL_TEXTURE_2D, texColorBuffer);
glTexImage2D(GL_TEXTURE_2D, 0, GL_RGB, width, height, 0, GL_RGB, GL_UNSIGNED_BYTE, NULL);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MIN_FILTER, GL_LINEAR);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAG_FILTER, GL_LINEAR);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_WRAP_S, GL_CLAMP_TO_EDGE);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_WRAP_T, GL_CLAMP_TO_EDGE);

// 3. 附加纹理到 FBO
glFramebufferTexture2D(GL_FRAMEBUFFER, GL_COLOR_ATTACHMENT0, GL_TEXTURE_2D, texColorBuffer, 0);

// 4. 创建 RBO（深度+模板）
unsigned int rbo;
glGenRenderbuffers(1, &rbo);
glBindRenderbuffer(GL_RENDERBUFFER, rbo);
glRenderbufferStorage(GL_RENDERBUFFER, GL_DEPTH24_STENCIL8, width, height);

// 5. 附加 RBO 到 FBO
glFramebufferRenderbuffer(GL_FRAMEBUFFER, GL_DEPTH_STENCIL_ATTACHMENT, GL_RENDERBUFFER, rbo);

// 6. 检查完整性
if (glCheckFramebufferStatus(GL_FRAMEBUFFER) != GL_FRAMEBUFFER_COMPLETE)
    std::cerr << "帧缓冲不完整!" << std::endl;

// 7. 恢复默认帧缓冲
glBindFramebuffer(GL_FRAMEBUFFER, 0);
```

### 3.2 API 速查

| API | 作用 |
|-----|------|
| `glGenFramebuffers` | 创建 FBO 对象 |
| `glBindFramebuffer` | 绑定 FBO（0 = 默认帧缓冲） |
| `glFramebufferTexture2D` | 将纹理作为附件附加到 FBO |
| `glFramebufferRenderbuffer` | 将 RBO 作为附件附加到 FBO |
| `glCheckFramebufferStatus` | 检查 FBO 完整性 |
| `glDeleteFramebuffers` | 删除 FBO |

### 3.3 绑定目标

| `glBindFramebuffer` 目标 | 含义 |
|--------------------------|------|
| `GL_FRAMEBUFFER` | 同时绑定读写 |
| `GL_READ_FRAMEBUFFER` | 只读绑定 |
| `GL_DRAW_FRAMEBUFFER` | 只写绑定 |

## 4. 颜色附件：纹理 vs RBO

### 4.1 为什么颜色附件用纹理？

因为我们接下来要**采样**它做后处理：

```glsl
uniform sampler2D screenTexture;
vec3 color = texture(screenTexture, TexCoords).rgb;
```

如果颜色附件是 RBO，着色器就无法采样它。

### 4.2 纹理参数设置

```cpp
// ★ 注意：纹理尺寸与窗口相同
glTexImage2D(GL_TEXTURE_2D, 0, GL_RGB, SCR_WIDTH, SCR_HEIGHT, 0, GL_RGB, GL_UNSIGNED_BYTE, NULL);

// 环绕方式用 CLAMP —— 全屏四边形 uv 正好覆盖 [0,1]
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_WRAP_S, GL_CLAMP_TO_EDGE);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_WRAP_T, GL_CLAMP_TO_EDGE);

// 不需要 mipmap —— 全屏采样不需要多级渐远
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MIN_FILTER, GL_LINEAR);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAG_FILTER, GL_LINEAR);
```

## 5. 深度/模板附件：渲染缓冲对象（RBO）

### 5.1 为什么深度/模板用 RBO？

我们不需要采样深度/模板值（只需要 OpenGL 内部用它们做测试），RBO 比纹理更高效：

- RBO 是 GPU 原生格式，免去纹理的格式转换
- 写入带宽更优
- 创建更简单

### 5.2 RBO 创建

```cpp
unsigned int rbo;
glGenRenderbuffers(1, &rbo);
glBindRenderbuffer(GL_RENDERBUFFER, rbo);

// GL_DEPTH24_STENCIL8：24 位深度 + 8 位模板 = 32 位，完美对齐
glRenderbufferStorage(GL_RENDERBUFFER, GL_DEPTH24_STENCIL8, width, height);

// 附加到帧缓冲
glFramebufferRenderbuffer(GL_FRAMEBUFFER, GL_DEPTH_STENCIL_ATTACHMENT, GL_RENDERBUFFER, rbo);
```

### 5.3 常见内部格式

| 格式 | 含义 |
|------|------|
| `GL_DEPTH24_STENCIL8` | 24bit 深度 + 8bit 模板（推荐，32bit 对齐） |
| `GL_DEPTH_COMPONENT16/24/32` | 纯深度 |
| `GL_STENCIL_INDEX8` | 纯模板 |

## 6. 完整性检查

```cpp
if (glCheckFramebufferStatus(GL_FRAMEBUFFER) == GL_FRAMEBUFFER_COMPLETE)
    // ✓ 可以使用
else
    // ✗ 有问题，检查以下条件
```

### 6.1 完整性条件

| 条件 | 说明 |
|------|------|
| 至少有一个附件 | 空帧缓冲无效 |
| 所有附件尺寸相同 | 颜色、深度、模板附件尺寸必须一致 |
| 内部格式兼容 | 颜色附件数量不超过 GPU 限制 |
| 附件类型有效 | 纹理格式必须对帧缓冲友好 |

### 6.2 常见错误

| 返回值 | 含义 |
|--------|------|
| `GL_FRAMEBUFFER_COMPLETE` | ✓ 完整 |
| `GL_FRAMEBUFFER_INCOMPLETE_ATTACHMENT` | 附件无效 |
| `GL_FRAMEBUFFER_INCOMPLETE_MISSING_ATTACHMENT` | 没有附件 |
| `GL_FRAMEBUFFER_INCOMPLETE_DRAW_BUFFER` | 绘制缓冲区不完整 |
| `GL_FRAMEBUFFER_UNSUPPORTED` | 格式不支持 |

## 7. 两遍渲染流程

### 7.1 核心代码

```cpp
// ============================================================
// ★ 第一遍：渲染场景到自定义帧缓冲
// ============================================================
glBindFramebuffer(GL_FRAMEBUFFER, fbo);
glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT);
glEnable(GL_DEPTH_TEST);

sceneShader.use();
// ... 设置 MVP 矩阵 ...
// ... 绘制地板、立方体等 ...

// ============================================================
// ★ 第二遍：渲染全屏四边形到默认帧缓冲（后处理）
// ============================================================
glBindFramebuffer(GL_FRAMEBUFFER, 0);  // 恢复到屏幕
glClear(GL_COLOR_BUFFER_BIT);
glDisable(GL_DEPTH_TEST);  // 全屏四边形不需要深度测试

screenShader.use();
screenShader.setInt("effect", currentEffect);
glActiveTexture(GL_TEXTURE0);
glBindTexture(GL_TEXTURE_2D, texColorBuffer);  // ★ 采样 FBO 的颜色纹理
glBindVertexArray(quadVAO);
glDrawArrays(GL_TRIANGLES, 0, 6);
```

### 7.2 流程图

```
        第一遍                                 第二遍
   ┌──────────────┐                    ┌──────────────┐
   │  绑定 FBO    │                    │ 绑定默认 FBO │
   │  glClear()   │                    │  glClear()   │
   │  绘制场景    │                    │  画全屏四边形 │
   │              │                    │  采样FBO纹理  │
   │  输出到      │                    │  应用后处理   │
   │  FBO纹理     │ ──→ 纹理作为输入 → │              │
   └──────────────┘                    │  输出到屏幕   │
                                       └──────────────┘
```

## 8. 全屏四边形与屏幕着色器

### 8.1 全屏四边形顶点数据

```cpp
// NDC 坐标 + 纹理坐标（每顶点 4 个 float）
float quadVertices[] = {
    // NDC pos        tex coord
    -1.0f, -1.0f,     0.0f, 0.0f,   // 左下
     1.0f, -1.0f,     1.0f, 0.0f,   // 右下
     1.0f,  1.0f,     1.0f, 1.0f,   // 右上

    -1.0f, -1.0f,     0.0f, 0.0f,   // 左下
     1.0f,  1.0f,     1.0f, 1.0f,   // 右上
    -1.0f,  1.0f,     0.0f, 1.0f    // 左上
};
```

### 8.2 为什么用 NDC 坐标？

- 全屏四边形直接覆盖整个屏幕，不需要 MVP 变换
- NDC 范围 [-1, 1] × [-1, 1] 就是裁剪空间的"整个屏幕"
- 顶点着色器直接输出：`gl_Position = vec4(aPos.x, aPos.y, 0.0, 1.0);`

### 8.3 屏幕着色器 uniform

```cpp
screenShader.setInt("screenTexture", 0);
screenShader.setInt("effect", currentEffect);
screenShader.setFloat("time", glfwGetTime());

// 像素偏移 = 1 / 纹理尺寸，用于 3×3 卷积核
screenShader.setFloat("texOffsetX", 1.0f / SCR_WIDTH);
screenShader.setFloat("texOffsetY", 1.0f / SCR_HEIGHT);
```

## 9. 后处理效果详解

### 9.1 效果列表

| 编号 | 效果 | 算法 | 性能 |
|------|------|------|------|
| 0 | Normal | `color` 直通 | 最低 |
| 1 | Inversion | `1.0 - color` | 低 |
| 2 | Grayscale | `0.2126R + 0.7152G + 0.0722B` | 低 |
| 3 | Sharpen | 3×3 锐化卷积核 | 中 |
| 4 | Blur | 3×3 高斯模糊核 | 中 |
| 5 | Edge Detection | 3×3 拉普拉斯算子 | 中 |

### 9.2 Normal（直通）

```glsl
if (effect == 0) {
    FragColor = vec4(texture(screenTexture, TexCoords).rgb, 1.0);
    return;
}
```

不加任何处理，原样输出。

### 9.3 Inversion（反色）

```glsl
if (effect == 1) {
    vec3 color = texture(screenTexture, TexCoords).rgb;
    FragColor = vec4(1.0 - color, 1.0);
    return;
}
```

每个颜色通道取反（1 减去原值）。暗部变亮，亮部变暗，产生"负片"效果。

### 9.4 Grayscale（灰度）

```glsl
if (effect == 2) {
    vec3 color = texture(screenTexture, TexCoords).rgb;
    float gray = 0.2126 * color.r + 0.7152 * color.g + 0.0722 * color.b;
    FragColor = vec4(vec3(gray), 1.0);
    return;
}
```

**为什么用加权平均而不是简单平均？**

| 方法 | 公式 | 效果 |
|------|------|------|
| 简单平均 | `(R+G+B)/3` | 偏蓝偏绿，不符合人眼感知 |
| 感知加权 ★ | `0.2126R + 0.7152G + 0.0722B` | 正确反映人眼对亮度的感知 |

人眼对绿色最敏感（占了约 71.5%），对蓝色最不敏感（只占约 7.2%）。

## 10. 卷积核（Kernel）基础

效果 3~5 都使用 3×3 卷积核（核卷积，Kernel Convolution）。

### 10.1 工作原理

```
采样中心像素及周围 8 个邻居 → 每个像素乘以核权重 → 相加 → 新颜色

采样位置：
    [0] 左上   [1] 中上   [2] 右上
    [3] 左中   [4] 中心   [5] 右中
    [6] 左下   [7] 中下   [8] 右下
```

### 10.2 三种卷积核对比

```
锐化 (Sharpen)             模糊 (Blur)                 边缘检测 (Edge)
┌────┬────┬────┐         ┌─────┬─────┬─────┐         ┌────┬────┬────┐
│ -1 │ -1 │ -1 │         │1/16 │2/16 │1/16 │         │  1 │  1 │  1 │
├────┼────┼────┤         ├─────┼─────┼─────┤         ├────┼────┼────┤
│ -1 │  9 │ -1 │         │2/16 │4/16 │2/16 │         │  1 │ -8 │  1 │
├────┼────┼────┤         ├─────┼─────┼─────┤         ├────┼────┼────┤
│ -1 │ -1 │ -1 │         │1/16 │2/16 │1/16 │         │  1 │  1 │  1 │
└────┴────┴────┘         └─────┴─────┴─────┘         └────┴────┴────┘
  权重和 = 1               权重和 = 1                  权重和 = 1
  增强中心差异             加权平均（中心权重最大）      检测变化率（类似导数）
```

### 10.3 像素偏移量

```cpp
// texOffsetX = 1.0 / 纹理宽度
// texOffsetY = 1.0 / 纹理高度

vec2 offsets[9] = vec2[](
    vec2(-texOffsetX,  texOffsetY),  // 左上
    vec2( 0.0,          texOffsetY),  // 中上
    vec2( texOffsetX,  texOffsetY),  // 右上
    vec2(-texOffsetX,  0.0),         // 左中
    vec2( 0.0,         0.0),         // 中心
    vec2( texOffsetX,  0.0),         // 右中
    vec2(-texOffsetX, -texOffsetY),  // 左下
    vec2( 0.0,        -texOffsetY),  // 中下
    vec2( texOffsetX, -texOffsetY)   // 右下
);
```

### 10.4 卷积实现

```glsl
vec3 samples[9];
for (int i = 0; i < 9; i++)
    samples[i] = texture(screenTexture, TexCoords + offsets[i]).rgb;

float kernel[9] = float[](...);  // 具体核值
vec3 result = vec3(0.0);
for (int i = 0; i < 9; i++)
    result += samples[i] * kernel[i];
FragColor = vec4(result, 1.0);
```

## 11. 翻转纹理问题

### 11.1 问题的原因

OpenGL 的纹理坐标系原点在**左下角**，而屏幕坐标系（默认帧缓冲）原点在**左上角**。当 FBO 的颜色纹理直接渲染到屏幕时，画面会**上下颠倒**。

```
纹理坐标系 (OpenGL)              屏幕坐标系
  (0,1) ─── (1,1)               (0,0) ─── (1,0)
    │         │                    │         │
    │    ↑    │                    │    ↓    │
    │    │    │                    │    │    │
    │    y    │                    │    y    │
    │         │                    │         │
  (0,0) ─── (1,0)               (0,1) ─── (1,1)
```

### 11.2 解决方案

**方案一：在顶点数据中翻转纹理坐标**

```cpp
// 全屏四边形中 uv.y 翻转
float quadVertices[] = {
    -1.0f, -1.0f,     0.0f, 1.0f,   // 左下 → uv.y = 1
     1.0f, -1.0f,     1.0f, 1.0f,   // 右下 → uv.y = 1
    // ...
};
```

**方案二：在着色器中翻转**

```glsl
TexCoords = vec2(aTexCoord.x, 1.0 - aTexCoord.y);
```

**方案三：通过 uniform 控制（Demo 中采用）**

```cpp
// 翻转时改变 texOffsetY 符号（仅用于演示对比）
if (flipVertical)
    screenShader.setFloat("texOffsetY", -1.0f / SCR_HEIGHT);
```

### 11.3 实际处理

在我们的 Demo 中，全屏四边形的顶点数据**已经做了翻转**（纹理 uv 直接匹配 OpenGL 纹理坐标系），所以默认情况下画面是正确的。`F` 键的翻转是为了**演示对比**这种差异。

4. **Sharpen**：画面更锐利，边缘更明显
5. **Blur**：画面柔和模糊，噪声被平滑
6. **Edge Detection**：只有边缘线，其余为黑底

---

## 13. 关键知识点总结

### 13.1 概念篇

| 概念 | 一句话解释 |
|------|-----------|
| 帧缓冲 (FBO) | GPU 渲染的目标，可以离屏渲染 |
| 颜色附件 | 存储片段着色器输出的颜色 |
| 深度附件 | 存储深度值，用于深度测试 |
| 模板附件 | 存储模板值，用于模板测试 |
| RBO | GPU 原生存储对象，写入快但不能采样 |
| 离屏渲染 | 渲染到纹理而非屏幕 |

### 13.2 API 篇

| API | 关键点 |
|-----|--------|
| `glBindFramebuffer(GL_FRAMEBUFFER, fbo)` | 绑定 FBO，0 = 默认帧缓冲 |
| `glFramebufferTexture2D` | 纹理作为帧缓冲附件 |
| `glFramebufferRenderbuffer` | RBO 作为帧缓冲附件 |
| `glCheckFramebufferStatus` | 必须返回 `GL_FRAMEBUFFER_COMPLETE` |

### 13.3 设计决策

| 场景 | 推荐方案 |
|------|---------|
| 需要采样附件 | 纹理（如颜色附件做后处理） |
| 不需要采样 | RBO（如深度/模板不采样） |
| 深度+模板一起用 | `GL_DEPTH24_STENCIL8` RBO（一次绑定两个） |
| 多渲染目标 (MRT) | 使用 `GL_COLOR_ATTACHMENT0` ~ N |

## 14. 下一步 / 预告

帧缓冲是后处理的基础。有了它之后可以做的扩展：

- **立方体贴图**：用帧缓冲将场景渲染到立方体贴图的 6 个面
- **泛光 (Bloom)**：高亮区域模糊后叠加，产生发光效果
- **HDR**：用浮点纹理存储超出 [0,1] 的颜色，再做色调映射
- **延迟渲染**：G-buffer 存储位置/法线/颜色等多附件
- **SSAO**：屏幕空间环境光遮蔽

下一章将学习 **立方体贴图（Cubemaps）**——天空盒和环境映射的基础。
