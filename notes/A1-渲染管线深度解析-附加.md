## 1. CPU 到 GPU 的完整管线流程

### 1.1 整体概览

以一个场景为例：**地板 + 两个不同深度的立方体**，从 CPU 到 GPU 的完整流程：

```
┌─────────────────────────────────────────────────────────┐
│ CPU 端（每帧）                                           │
│                                                         │
│ ① 更新 MVP 矩阵                                          │
│    projection = glm::perspective(fov, ...)               │
│    view       = glm::lookAt(camPos, ...)                 │
│    model      = glm::translate(...) * glm::rotate(...)   │
│                                                         │
│ ② 设置 OpenGL 状态                                       │
│    glEnable(GL_DEPTH_TEST)                               │
│    glEnable(GL_CULL_FACE)                                │
│    glDepthFunc(GL_LESS)                                  │
│                                                         │
│ ③ 按顺序发出 Draw Call                                   │
│    glDrawArrays(地板)           // 第 1 个 Draw Call      │
│    glDrawElements(立方体 1)     // 第 2 个 Draw Call      │
│    glDrawElements(立方体 2)     // 第 3 个 Draw Call      │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────┐
│ GPU 端（每个 Draw Call）                                  │
│                                                         │
│ 顶点数据 → 顶点着色器 → 光栅化 → 片段着色器 → 深度测试 → 帧缓冲│
│              ↑              ↑              ↑             │
│           MVP 矩阵     生成像素片段   glDepthFunc(LESS)   │
│                                                         │
│ ★ 深度缓冲在所有 Draw Call 之间持续累积                    │
└─────────────────────────────────────────────────────────┘
```

### 1.2 每个 Draw Call 内部：按三角形顺序

```
glDrawElements(立方体 1, 36 个索引)  →

  三角形 0（背面）:  顶点 → 光栅化 → 片段 → ★深度测试→ 帧缓冲  │
  三角形 1（背面）:  顶点 → 光栅化 → 片段 → ★深度测试→ 帧缓冲   │← 深度缓冲
  三角形 2（正面）:  顶点 → 光栅化 → 片段 → ★深度测试→ 帧缓冲  │  持续累积
  ...                                                       │
  三角形 11（顶面）: 顶点 → 光栅化 → 片段 → ★深度测试→ 帧缓冲 │
                                                             ▼
                                                        深度缓冲 = 最新值
```

> **关键：** 同一个 `glDrawElements` 调用内，三角形按索引数组的顺序依次处理。先画的三角形可以被后画的、更近的三角形覆盖，**哪怕它们属于同一个物体**。

## 2. 渲染顺序：物体 → 网格 → 三角形 → 像素

### 2.1 层级结构

```
场景
  ├── 物体 A（如：人物模型）
  │     ├── 网格 0（头盔）     → 1 次 Draw Call
  │     ├── 网格 1（身体）     → 1 次 Draw Call
  │     └── 网格 2（手臂）     → 1 次 Draw Call
  │           └── 三角形 0    → 3 个顶点 → 完整管线
  │           └── 三角形 1    → 3 个顶点 → 完整管线
  │           └── ...         (深度缓冲持续累积)
  │
  ├── 物体 B（另一个模型）      → 多次 Draw Call
  └── ...
```

### 2.2 对应代码

```cpp
// 一个 Model 有多个 Mesh
void Model::Draw(Shader& shader)
{
    for (Mesh& mesh : meshes)       // 遍历所有网格
    {
        mesh.Draw(shader);          // 每个网格 = 一次 Draw Call
        // 内部: glBindVertexArray(VAO)
        //       glDrawElements(GL_TRIANGLES, indexCount, ...)
    }
}
```

### 2.3 深度缓冲的全局性

**深度缓冲从第一个 Draw Call 的第一个三角形开始累积，到最后一个 Draw Call 的最后一个三角形结束。** 所有物体、所有网格共享同一个深度缓冲。

## 3. 深度测试的工作原理

### 3.1 基本流程

每个片段在写入帧缓冲前，经历深度测试：

```
片段到达 → 读取深度缓冲中同位置的深度值 → 比较（默认 GL_LESS）
                                              │
                          ┌───────────────────┴───────────────────┐
                          ▼                                       ▼
                    新深度 < 旧深度                                新深度 ≥ 旧深度
                    （更近）                                      （更远或相等）
                          │                                       │
                          ▼                                       ▼
                    写入深度缓冲                                    丢弃
                    写入颜色缓冲                                  （不显示）
```

### 3.2 三个物体的深度变化过程

初始深度缓冲 = 1.0（最远值）。同一像素位置的深度值变化：

| 步骤 | 操作 | 新片段深度 | 比较结果 | 深度缓冲变成 | 屏幕显示 |
|---|---|---|---|---|---|
| ① | 地板写入 | 0.9 | 0.9 < 1.0 通过 | 0.9 | 地板色 |
| ② | 立方体 1 背面 | 0.5 | 0.5 < 0.9 通过 | 0.5 | 容器纹理 |
| ③ | 立方体 1 **正面** | **0.3** | **0.3 < 0.5 通过** | **0.3** | **容器纹理** |
| ④ | 立方体 2 | 0.7 | 0.7 < 0.3 **失败** | 0.3（不变） | 不变 |

第④步立方体 2 的片段深度 0.7 > 当前缓冲的 0.3，**被丢弃**，屏幕上保持立方体 1 的颜色。

### 3.3 深度测试开关的效果

| 状态 | 行为 | 结果 |
|---|---|---|
| **深度测试 ON** | 每个片段和深度缓冲比较，更近的通过 | 正确遮挡，远近距离决定可见性 |
| **深度测试 OFF** | 所有片段无条件通过，**最后绘制的赢** | 绘制顺序决定可见性，后画的覆盖先画的 |

## 4. 面剔除（Face Culling）与绕序

### 4.1 为什么要面剔除？

在不透明物体中，**背对相机的面永远不可见**。面剔除让 GPU 跳过这些面的片段着色器。

### 4.2 绕序（Winding Order）

三角形的顶点顺序决定了它的正面/背面：

```
OpenGL 默认约定：
  逆时针（CCW）= 正面   → 渲染
  顺时针（CW） = 背面   → 剔除（默认）
```

确定绕序的方法：用叉积计算法线方向

```
对于三角形 A→B→C：
  Edge1 = B - A
  Edge2 = C - A
  Normal = Edge1 × Edge2

如果 Normal 指向外部 → 三角形是逆时针（CCW）→ 正面
如果 Normal 指向内部 → 三角形是顺时针（CW） → 背面
```

### 4.3 常见场景：绕序错误的是什么样的？

下面是一个**立方体六个面中三个面绕序反了**的例子（实际遇到了这个问题）：

```
正面（z=0.5）: 法线 (0,0,1)  = +Z ✓ 指向外部
背面（z=-0.5）: 法线 (0,0,1)  = +Z ✗ 指向内部（应指向 -Z）
左面（x=-0.5）: 法线 (-1,0,0) = -X ✓ 指向外部
右面（x=0.5）:  法线 (-1,0,0) = -X ✗ 指向内部（应指向 +X）
顶面（y=0.5）:  法线 (0,-1,0) = -Y ✗ 指向内部（应指向 +Y）
底面（y=-0.5）: 法线 (0,-1,0) = -Y ✓ 指向外部
```

三个面绕序反了 → 开启面剔除后它们被当作"背面"剔除 → 立方体缺面。

**修正方法：** 交换每个三角形中两个顶点的顺序（A,B,C → A,C,B）。

### 4.4 面剔除 + 深度测试的关系

| 面剔除 | 深度测试 | 效果 |
|---|---|---|
| ON | ON | ✅ 只渲染外表面，正确遮挡（标准 3D） |
| ON | OFF | 只渲染外表面，但后画的覆盖先画的（缺深度判断） |
| OFF | ON | 内外都渲染，但深度测试决定可见性（性能浪费） |
| OFF | OFF | 内外都渲染，后画的赢（画面混乱） |

**推荐做法：两个都开启。**

## 5. Early-Z 优化

### 5.1 什么是 Early-Z

Early-Z（提前深度测试）是 GPU 硬件优化，在**片段着色器之前**做一次深度比较：

```
传统管线：
  片段着色器（算纹理、算光照） → 深度测试 → 丢弃/写入
                                   ↑
                              晚了，白算了

Early-Z 管线：
  Early-Z（提前比较） → 通过 → 片段着色器 → Late-Z（最终确认）
       │                       │
       ▼                       ▼
     丢弃                   写入帧缓冲
  （不用算片段着色器）
```

### 5.2 Early-Z 节省了什么？

以一个人物模型为例，三角形按顺序渲染：

```
三角形顺序（固定索引顺序）：
  三角形  0: 鼻子（凸出，顶点在最前面）  → 深度 0.1 → 写入深度
  三角形  1~1000: 脸（在鼻子后面）       → 深度 0.3
                                          → Early-Z: 0.3 > 0.1
                                          → ✗ 丢弃（省了片段着色器！）

  ★ 999 个三角形的片段着色器被省掉了！
```

### 5.3 Early-Z 的局限性

Early-Z 只在以下条件**全部满足**时才能工作：

| 条件 | 如果违反 |
|---|---|
| 片段着色器没有写 `gl_FragDepth` | 输出深度未知，没法提前比较 |
| 没有使用 `discard` 或 Alpha 测试 | 不知道片段会不会被丢弃 |
| 没有混合（Blend） | 混合需要特定顺序 |
| 不透明物体 | 半透明需要排序 |

### 5.4 三角形顺序对 Early-Z 的影响

Early-Z 的节省效果 = **三角形渲染顺序 × 摄像机位置** 的匹配度。

| 场景 | 节省效果 | 原因 |
|---|---|---|
| **先画的三角形刚好挡住后面大量三角形** | ✅ **极好** | 后面的 Early-Z 全丢 |
| **三角形顺序混乱（近→远→近→远）** | ❌ 差 | 反复覆盖，Early-Z 失效 |
| **物体是凸的（立方体、球）** | ⚠️ 一般 | 每个面位置不同，遮挡少 |
| **物体有大量内部细节（人物、植物）** | ✅ **很好** | 大量三角形被自己挡住 |

## 6. GPU 并行架构

### 6.1 统一着色器架构

现代 GPU（NVIDIA 从 GeForce 8800 开始）采用 **统一着色器架构（Unified Shader）**：

```
旧架构（独立单元）:         现代架构（统一核心）:

顶点处理器 ██████          着色器核心 × 数千个
像素处理器 ██████           █ █ █ █ █ █ █ █ █ █
                           █ █ █ █ █ █ █ █ █ █
负载不均，摸鱼严重           █ █ █ █ █ █ █ █ █ █
                           每个核心可跑任何着色器
                           动态分配，负载均衡
```

### 6.2 SIMT（单指令多线程）

GPU 的并行方式：**几千个核心同时运行同一个着色器程序，但处理不同的数据。**

```
GPU 有 2048 个核心：
  100 个顶点  → 一次就能处理完
  10000 个顶点 → 分 5 批处理
```

### 6.3 着色器核心 vs ROP

```
着色器核心（可编程）              ROP（固定硬件）
████████████████████            ████████
 顶点着色器                      深度测试
 几何着色器                      模板测试
 片段着色器                      颜色混合
                                  写入帧缓冲
```

- **着色器核心**：可编程，负责所有着色器阶段
- **ROP（光栅输出单元）**：固定硬件，负责深度测试、混合等，极快且不可编程

## 7. Draw Call 详解

### 7.1 什么是 Draw Call

**一次 Draw Call = CPU 告诉 GPU："用当前的着色器和状态，渲染这批顶点数据。"**

```cpp
mesh.Draw(shader);    // 内部就是 glDrawElements(...)
                      // 这就是一次 Draw Call
```

### 7.2 Draw Call 的开销

```
CPU                     GPU
  │                       │
  ├── glBindTexture() ──→ │ 设置纹理
  ├── glUniform() ──────→ │ 设置参数
  ├── glDrawElements() ─→ │ ▲ 真正开始干活
  │                       │ │
  │  CPU 等待 GPU 返回    │ │ 渲染这批三角形
  │  （这期间 CPU 闲着）   │ │
  │                       │ ▼
  │                       │
  ├── glBindTexture() ──→ │ 下一个网格，重复
  ├── glUniform() ──────→ │
  ├── glDrawElements() ─→ │
```

**性能参考：**

| Draw Call 数量 | 影响 |
|---|---|
| ~100 | 轻松 |
| ~1000 | 正常游戏 |
| ~10000 | CPU 开始成为瓶颈 |
| ~100000 | CPU 满载，帧率暴跌 |

### 7.3 优化：合并 Draw Call

多个小网格合并成一个大网格，一次 Draw Call 画完。这叫做**批处理（Batching）**。

## 8. Z-prepass（提前深度预渲染）

### 8.1 为什么要 Z-prepass？

Early-Z 只能省**同一个物体内部**的片段着色器。对于**先渲染的物体被后渲染的物体挡住**的情况，先渲染的物体的片段着色器已经白算了。

Z-prepass 的解决思路：**先画一遍纯深度，再正式渲染。**

### 8.2 Z-prepass 流程

```
Pass 1（深度预渲染）：
  所有物体 → 顶点着色器 → 只写深度 → 不要颜色
  最终：深度缓冲填满了所有物体的最近深度值

Pass 2（正式渲染）：
  所有物体 → 顶点着色器 → Early-Z（已有完整深度）
           → 被遮挡的像素直接丢弃 → 片段着色器 → 只算可见的

  ★ 被挡住的地板像素在 Early-Z 阶段就被丢弃
  ★ 完全不用算片段着色器
```

### 8.3 Z-prepass 的代价

- **顶点着色器跑了两次**（Pass 1 和 Pass 2 各一次）
- 对于顶点多的场景，可能得不偿失
- 现代 GPU 的 Early-Z + Hierarchical Z 已经足够高效，Z-prepass 不再是主流优化

## 9. 常见问题

### Q1：深度测试和透明度（Alpha）的关系？

深度测试在**片段着色器之后**，如果片段使用了 `discard`（如 Alpha 测试），深度值不会被写入。这是 Early-Z 失效的原因之一。

### Q2：半透明物体怎么处理深度测试？

半透明物体需要**从远到近排序后绘制**，并且**关闭深度写入**但**保留深度读取**：

```cpp
glDepthMask(GL_FALSE);     // 不写深度
// 画半透明物体（从远到近）
glDepthMask(GL_TRUE);      // 恢复深度写入
```

### Q3：gl_FragCoord.z 的值范围？

| 范围 | 含义 |
|---|---|
| 0.0 | 在近平面上 |
| 1.0 | 在远平面上 |
| 非线性 | 近处精度高，远处精度低 |

### Q4：同一个 Vertices 数据，多个物体怎么共享？

通过 VAO + VBO 的绑定机制：

```cpp
// 两个 VAO 共享同一个 VBO
unsigned int VAO1, VAO2, VBO;
glBindVertexArray(VAO1);
glBindBuffer(GL_ARRAY_BUFFER, VBO);
glVertexAttribPointer(...);  // VAO1 记住了 VBO 的绑定

glBindVertexArray(VAO2);
glBindBuffer(GL_ARRAY_BUFFER, VBO);
glVertexAttribPointer(...);  // VAO2 也记住了同一个 VBO
```
